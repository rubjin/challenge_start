파일 구조 및 문서 규칙

본 문서는 챌린지 프로젝트의 퍼블리싱 작업에 대한 파일 구조, 네이밍 컨벤션, 코딩 규칙을 정의합니다.
개발팀이 React(JSX) 환경으로 원활하게 이관할 수 있도록 가이드하기 위해 작성되었습니다.

1. 파일 구조 (Directory Structure)

챌린지_start/
├── index.html                # 전체 퍼블리싱 산출물 목록 (Worksheet)
└── src/
    ├── html/                 # HTML 산출물 폴더
    │   ├── convention.html   # 파일 구조 및 문서 규칙 (현재 파일)
    │   ├── guide.html        # 공통 UI 컴포넌트 가이드
    │   ├── challenge/        # 챌린지 관련 화면
    │   └── admin/            # 어드민 관련 화면
    │
    ├── images/               # 이미지(png, jpg, svg 등) 폴더
    │
    ├── scss/                 # SCSS 소스 폴더 (실제 작업 영역)
    │   ├── base/             # Reset, Variables(변수), Mixins, 전역 스타일
    │   ├── components/       # 버튼, 뱃지, 카드 등 재사용 가능한 UI 컴포넌트
    │   ├── pages/            # 특정 페이지에 종속된 레이아웃 및 스타일
    │   └── main.scss         # 모든 partial SCSS를 import하는 진입점
    │
    └── css/                  # 컴파일된 최종 CSS 폴더 (개발팀 전달용)
        └── main.css

2. 네이밍 컨벤션 (CSS Naming Convention)

  • 기존 운영 중인 프로젝트와의 스타일 충돌을 방지하기 위해 BEM (Block__Element--Modifier) 방법론에 네임스페이스(ch-)를 결합하여 사용합니다.
  • Prefix (접두사): 모든 클래스명은 ch-로 시작합니다.
  • Block (블록): 독립적인 의미를 가지는 컴포넌트 단위 (예: .ch-btn, .ch-card)
  • Element (요소): 블록에 종속된 하위 요소는 __ 로 연결 (예: .ch-card__title)
  • Modifier (상태/변형): 속성이 다를 때는 -- 로 연결 (예: .ch-btn--primary)
  • State (동적 상태): JS나 React 상태로 제어되는 동적 클래스는 is- 접두사 사용 (예: .is-active)

3. HTML / 문서 작성 규칙

  1. 들여쓰기: Space 2칸을 표준으로 사용합니다.
  2. 빈 태그 닫기: <img />, <input />, <br /> 등은 React 환경을 고려해 반드시 슬래시로 닫습니다.
  3. 인라인 스타일 금지: style="..." 속성은 원칙적으로 배제하고 모든 디자인은 CSS로 제어합니다.
  4. 의미론적 마크업: <div> 남용을 줄이고 <header>, <nav>, <article> 등을 적극 활용합니다.
  5. 접근성(A11y): 버튼 태그에는 항상 type="button"을 명시하고, 스크린 리더용 텍스트는 .ch-a11y-hidden 클래스를 사용해 숨김 처리합니다.

4. 컬러 및 테마 (Color System)

  • 국민은행의 아이덴티티를 반영한 컬러 시스템을 사용합니다.
  • Primary: #FFDC00 (KB Yellow)
  • Primary Hover: #E5C600 (Darker Gold)
  • Text/Point: #1f2937 (가독성을 위한 어두운 회색)

5. React 개발팀 인수인계 시 주의사항

  • 퍼블리싱 결과물의 class 속성은 React 적용 시 모두 className으로 일괄 변경하여 적용해야 합니다.
  • 탭, 아코디언 등의 인터랙션은 순수 HTML+CSS 상태 확인을 위해 .is-active를 수동 마크업해 두었습니다. 개발 적용 시 State 값에 따라 토글되도록 연동이 필요합니다.
